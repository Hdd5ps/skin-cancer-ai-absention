### 1. PROJECT CONTEXT
We are building a production-ready mobile skin cancer screening application (React Native/Expo frontend + FastAPI backend). 
We have completed the model training phase using PyTorch [1]. The core asset is a calibrated MobileNetV2 model (`mobilenetv2_calibrated.pth`) trained on 26,000+ ISIC lesion images [1, 7]. The training utilized nn.BCEWithLogitsLoss with a dynamic positive class weight of 58.16 to handle a severe (<2%) class imbalance [7, 8]. It achieved a validation AUC of 0.8884 and was calibrated using Temperature Scaling (T = 1.1672) to reduce the Expected Calibration Error (ECE) to 0.0730, ensuring reliable probability confidence scores [7].

### 2. CORE ARCHITECTURAL SYSTEM DESIGN
The application must adhere strictly to the Model-View-Controller (MVC) pattern and the principle of Functional Independence [4, 5]. Ensure High Functional Cohesion and Low Coupling by decoupling presentation layers from the underlying business logic [4, 9]:
- **Frontend (View/Controller):** Built with React Native, Expo, and Tailwind CSS (NativeWind) for portability [9].
- **Backend API (Model/Controller):** Built with FastAPI and Uvicorn [1].
- **Dual-Gated Pipeline (Business Logic):** Implement the decision flow sequentially:
  - **Gate 1 (Blurriness Filter):** Use OpenCV's Laplacian variance method to calculate image sharpness [1]. If the variance falls below a set threshold, immediately trigger an error state [10].
  - **Gate 2 (Confidence/Uncertainty Abstention):** Run confident images through the MobileNetV2 model, apply Temperature Scaling (T = 1.1672), and compute the probability [1, 7]. If the model's confidence is too low, abstain from returning a predicted label and trigger a clinical recommendation [10].

3. Practice Questions
What is the core difference between Software Quality Assurance (SQA) and Testing in this project?
Answer: Software Testing is a reactive quality control activity where we execute test cases on our FastAPI endpoints to find defects
. SQA is a proactive umbrella activity where we audit the entire process—enforcing coding standards, checking requirements traceability, and verifying that our automated CI pipeline runs on every code change to prevent errors
.
Why is Temperature Scaling (T=1.1672) considered a critical secure-by-design feature for a medical screening app?
Answer: Uncalibrated deep learning models are notoriously overconfident
. Applying temperature scaling calibrates raw model logits so that confidence matches real-world accuracy
. This lets us confidently set an uncertainty threshold (Gate 2), preventing the app from displaying a highly confident yet completely incorrect cancer prediction to a patient
.
